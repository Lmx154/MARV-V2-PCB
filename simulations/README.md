# Power simulations

Results live in [RESULTS.md](RESULTS.md) (generated by `python3 tools/run_power_checks.py`) — this file does not duplicate it.

Current design: [DESIGN_SPEC.md](../DESIGN_SPEC.md). The pre-2026-09-17 power tree (on-board AP63205 pack buck -> U25 TPS2121 priority mux -> U7 TPS62913 two-stage 3.3 V buck) was replaced by an external BEC -> Q1 AO3401A / D1 1N5819WS P-FET+Schottky OR -> fixed AP63203WU-7 3.3 V buck (DESIGN_SPEC.md "Decisions", 2026-09-17).

## Retired decks

`integrated_power.cir`, `source_handover.cir` and `enclosure_thermal.cir` modeled the removed tree and have been **retired, not re-derived**, per the lead's decision: they live in [`superseded/`](superseded/) together with their generated `corners/`. `tools/run_power_checks.py` no longer runs them and no longer reports a `Status: PASS` on their basis. Re-deriving decks for the current BEC + Q1/D1 + AP63203 tree — in particular the OR-ing FET's diode-hand-off crossover behaviour (not a controlled switchover) and the hold-up capacitor now sitting on 5V_IN rather than V5_SYS — is open work; see DESIGN_SPEC.md "Open items".

## Decks kept in place

`rail_load_step.cir`, `source_load_trade.cir` — older, independent, illustrative decks (a hypothetical 3.3 V rail step, and a dedicated-vs-shared actuator source/load trade) that never modeled the AP63205/TPS2121/TPS62913 tree or any other specific board part. Kept for reference; not driven by `run_power_checks.py`.

## How to run

```sh
python3 tools/run_power_checks.py
```

Rewrites `RESULTS.md`. With no live power-stage decks registered, this prints a `RETIRED:` status line and exits 0.
