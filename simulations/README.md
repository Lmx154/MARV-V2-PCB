# Power simulations

Results live in [RESULTS.md](RESULTS.md) (generated by `python3 tools/run_power_checks.py` with ngspice; carries its own `Status:` line) — this file does not duplicate its tables.

Current design: [DESIGN_SPEC.md](../DESIGN_SPEC.md). Evaluated against the V3V3_SYS budget (500 mA continuous / 800 mA peak <= 10 ms, typical ~300 mA) plus <= 50 mA on V3V3_ANA. 5 V-only: 5V_IN (J3) or USB (J4) into U25 TPS2121, a priority power mux (IN1 = 5V_IN priority, IN2 = USB_VBUS, OUT = V5_SYS), then U7 TPS62913 (buck, V3V3_SYS) and U12 TPS7A20 (LDO, V3V3_ANA). No cell/battery path; no USB current limiter modeled.

## Source model

U25 is modeled as a `muxctl` source-selection subckt (UV / OV1 / PR1 comparators and their hysteresis) plus one `muxpath` subckt per input channel (RON, tSW switchover, always-on reverse-current blocking via IRCB/tRCB). There is no body diode in this model: unlike the LM66100 pair it replaced, the TPS2121 blocks reverse current on both inputs at all times.

## Decks
- `integrated_power.cir` — both sources feeding V5_SYS through U25, the TPS62913 buck and the TPS7A20 LDO together, with a 500->800->500 mA V3V3_SYS load step and a constant 10 mA V3V3_ANA load.
- `source_handover.cir` — standalone U25 handover corner: one source (SURVIVOR) present for the whole run, the other (OTHER) removed or inserted at t=15 ms, using the same muxctl/muxpath model as `integrated_power.cir`.
- `enclosure_thermal.cir` — lumped single-node board thermal model driven by the buck+LDO conversion loss from `integrated_power.cir` plus the load budget's electronics heat figures.
- `rail_load_step.cir`, `source_load_trade.cir` — older, independent decks (a hypothetical 3.3 V rail step, and a dedicated-vs-shared actuator source/load trade) kept for reference; not part of the current model and not driven by `run_power_checks.py`.

## Corners (`corners/`)
`nominal`, `lossy_path`, `usb_only`, `bec_only`, `loss_300ma` — integrated source/load sweeps. `bec_removed_usb_present`, `usb_removed_bec_present`, `usb_insert_bec_present`, `usb_insert_onto_5vin` (typical/worst-case corners, plus a CSYS sensitivity sweep) — handover timing. `bec_overvoltage_6v5`, `misplug_2s_8v4` (typical/worst-case) — U25 OV1 lockout corners. `thermal_300mA_*`, `thermal_500mA_*` — enclosure thermal-resistance sweeps.

## How to run

```sh
python3 tools/run_power_checks.py
```

Rewrites `RESULTS.md` and exits non-zero if any design predicate is violated. To run a deck manually: `ngspice -b -o simulations/<name>.log simulations/<name>.cir`.

## What these simulations do and do not prove

These are behavioral models (muxctl/muxpath comparator logic for the TPS2121, assumed efficiency figures for the buck/LDO), not vendor SPICE macromodels. A `Status: PASS` in RESULTS.md means architectural margin only, not hardware sign-off. Remaining hardware validation:

- Vendor-model or bench checks for regulator loops, startup, current-limit behavior and source handover.
- USB enumeration/startup/inrush/suspend and higher-current control, including tolerance extremes.
- Real input transients, TVS/fuse coordination and reverse-current pulses.
- Logging and actuator-disturbance tests, and no-airflow enclosure thermal soak.
- Final MPNs, effective capacitance, inductor saturation/temperature and PCB layout.
