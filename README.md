# MARV V2 flight controller

Flight controller for rockets/drones that stacks on a MicoAir AM32 4-in-1 ESC (2-6S, no BEC): RP2354B MCU, ICM-45686 IMU, BMP581 barometer, ADXL375 high-g, microSD logging plus an optional (DNP, back-side) QSPI flash-or-PSRAM expansion socket, 8 PWM outputs (4 to the ESC, 4 servo), a 3-column x 14-row 2.54 mm THT IO block on the right edge (J6 signal / J7 power / J8 GND per row, 5 V or 3V3 depending on the row) carrying GPS / ELRS / magnetometer / the 4 servo outputs plus 4 exposed spare GPIO, a solder-pad ESC row (J3, vertical against the left edge) and DBG pad row (J10) plus 10 sensor-bus test points (TP1-TP10) and the unpopulated QSPI expansion land (U24/C62/C63), all on the back (B.Cu) so front-side assembly stays single-sided — nothing on the back is ever reflowed, battery monitoring off VBAT_SENSE and the ESC's current-sense output (no shunt-based coulomb counter), ESC current sense and KISS telemetry input, WS2812C RGB status LED, USB-C. Raw pack (6-25.2 V) comes in on the ESC pad row and an on-board AP63205 buck makes 5 V; USB is the fallback source through a TPS2121 priority mux. Solder pads only for the ESC row (J3) and the DBG landing (J10); every other external signal is on the 2.54 mm J6/J7/J8 IO block. Firmware and PCB layout are not done; the PCB is empty.

## File map

- [DESIGN_SPEC.md](DESIGN_SPEC.md) — power, rails, sheets, GPIO map, decisions.
- [LIBRARIES.md](LIBRARIES.md) — nonstandard parts and layout rules.
- [PINOUT.md](PINOUT.md) — the authoritative pin plan: every GPIO, its datasheet alternates, and what each J6 spare row can become.
- `*.kicad_sch` — 12 hierarchical sheets, one page per subsystem: root (an index of sheet blocks) + `power_vbat`, `power_mux`, `power_3v3`, `mcu`, `usb_debug`, `imu`, `baro`, `highg`, `sd`, `qspi_expansion`, `io_block`. On each page the IC is drawn with its own decoupling, pull-ups, series resistors, test points and connectors wired to it; global labels carry only the nets that leave the page. All of them are generated by `tools/build_power.py`.
- `tools/` — `build_power.py` (generator), `relink_pcb_paths.py` (re-points every footprint's `(path "/<sheet-uuid>/<symbol-uuid>")` after a symbol moves sheet), `netlist_fingerprint.py` (layout-independent connectivity fingerprint, for proving a re-organisation changed nothing electrical), `check_power_netlist.py`, `run_power_checks.py`, `audit_footprints.py` (footprint / 3D-model readiness).
- `tools/3d/` — FreeCAD scripts that generate the simplified STEP models, plus `bbox.py` (bounding box of a STEP); see [tools/3d/README.md](tools/3d/README.md).
- `tools/jlc/` — JLCPCB sourcing tools: `jlc_api.py` (JLC catalogue queries), `find_part.py` (parametric part search), `bom_lines.py` / `audit.py` (the unique-line audit and its sums), `export_jlc.py` (writes `reports/jlc-bom.csv` + `reports/jlc-cpl.csv`), and `lcsc_map.csv` (the single `(spec, footprint) -> LCSC part` table `tools/build_power.py` stamps onto every fitted symbol as a hidden `LCSC` property).
- `MARV_Packages.pretty/` — fifteen project-local footprints: nine official KiCad footprints vendored so they can carry project-local 3D models (including L2/L3, both CJIANG inductor footprints from KiCad's own `Inductor_SMD.pretty`) or (for the J6/J7/J8 IO block) a trimmed courtyard/silkscreen; three project-authored from a vendor drawing and carrying a 3D model (the sensor LGAs — ICM-45686, BMP581, ADXL375); and the project-authored solder pad rows (`PadRow_1x03/08_P2.00mm`, for J3 and J10) and the grommet mounting hole (`MountingHole_4.0mm_Grommet`), which carry no 3D model by design — same as the ten `TestPoint:TestPoint_Pad_1.0x1.0mm` test points (TP1-TP10), used directly from the KiCad official library.
- `MARV_Packages.3dshapes/` — the STEP models those footprints reference, with [provenance, licences and SHA256 sums](MARV_Packages.3dshapes/PROVENANCE.md).
- `simulations/` — ngspice decks and [results](simulations/README.md).
- `reports/` — ERC report, netlist export, schematic PDF, plus the JLCPCB order artifacts: [jlc-audit.md](reports/jlc-audit.md) (parts audit and quote parameter sheet), `jlc-bom.csv` / `jlc-cpl.csv` (JLC's own BOM/CPL order-form format, written by `tools/jlc/export_jlc.py`).
- [power_bom.csv](power_bom.csv) — preliminary BOM, not purchase-ready; the `Fit` column marks U24/C62/C63 as `DNP` (the optional QSPI expansion).
- `backups/` — pre-revision schematic and DESIGN_SPEC snapshots.

`tools/build_power.py` overwrites generated sheets: edit the generator, not the sheets.

## Reproduce checks

```sh
kicad-cli sch erc --severity-all --exit-code-violations -o reports/power-erc.rpt MARV-V2.kicad_sch
kicad-cli sch export netlist MARV-V2.kicad_sch --format kicadxml -o reports/power-netlist.xml
python3 tools/check_power_netlist.py reports/power-netlist.xml
python3 tools/netlist_fingerprint.py reports/power-netlist.xml   # diff two of these to prove a re-layout changed no connectivity
python3 tools/relink_pcb_paths.py                                # after tools/build_power.py: re-point the footprint paths
python3 tools/run_power_checks.py
kicad-cli sch export pdf MARV-V2.kicad_sch -o reports/MARV-V2-power.pdf
python3 tools/audit_footprints.py reports/power-netlist.xml
python3 tools/jlc/export_jlc.py   # writes reports/jlc-bom.csv + reports/jlc-cpl.csv from the netlist's LCSC properties
```

Python tools use the standard library; ngspice and kicad-cli must be installed.
`tools/jlc/export_jlc.py` additionally needs `reports/power-netlist.xml` (from the `kicad-cli sch export netlist` step above) and `MARV-V2.kicad_pcb`; see [reports/jlc-audit.md](reports/jlc-audit.md) for the full JLCPCB sourcing method, the audit and the quote parameter sheet.
