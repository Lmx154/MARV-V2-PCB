# Power simulations

Results live in [RESULTS.md](RESULTS.md) (generated by `python3 tools/run_power_checks.py`) —
this file does not duplicate them. It describes the method: what the decks are, which
models are vendor and which are behavioural, and how to run them.

Current design: [DESIGN_SPEC.md](../DESIGN_SPEC.md). The power tree is an external BEC →
`5V_IN` → Q1 AO3401A / D1 1N5819WS 5 V OR → `V5_SYS` → U7 AP63203WU-7 fixed 3.3 V buck →
`V3V3_SYS`, with U12 TPS7A2033 hanging off **`V5_SYS`** (not off `V3V3_SYS`; its EN is what
ties to `V3V3_SYS`) to make `V3V3_ANA` for the MEMS sensors.

## How to run

```sh
python3 tools/run_power_checks.py
```

It runs every corner, prints one `PASS`/`FAIL` line per predicate and one
`NEG-CONTROL …` line per negative control, rewrites [RESULTS.md](RESULTS.md), and **exits
non-zero if any predicate fails or if any negative control does not fail**. A negative
control that passes means the predicate cannot see the defect it exists to catch, so the
script treats that as its own failure, not as good news.

Needs `ngspice` on `PATH` (developed against ngspice-42).

## Structure of a deck, and how corners are made

Same convention the retired decks used, because the harness that drives them is the same
one: each deck carries a `.param` block at the top and a small number of **named
substitutable blocks** delimited by comments, e.g.

```
* --- USB SOURCE BLOCK: usb_on ---
Vusb vusb0 0 PWL(...)
Rusb vusb0 usbvbus {RUSB}
* --- END USB SOURCE BLOCK ---
```

`tools/run_power_checks.py` builds a corner by string-substituting those blocks or
individual `.param` assignments, writes the result to `corners/<name>.cir` — so the exact
text that ran is on disk and diffable — runs `ngspice -b`, and parses the `name = value`
lines that `.meas` prints. Any substitution target that is not found, any ngspice error,
and any missing or non-finite measurement aborts the run rather than producing a row.

Predicates are always `.meas` statements, never an eyeball on a waveform. Two conventions
carried over from the retired decks:

* **Settling time** is `.meas tran … INTEG par('(<out of band>) ? 1 : 0')` — the total time
  spent outside the band, which needs no edge detection and cannot be fooled by a
  waveform that leaves the band twice.
* **Thresholds in behavioural models are `tanh`, not `? :` or `min`/`max` clamps**, so the
  solver never has to step across a discontinuity in the state path.
* Monotonicity is measured, not asserted: `ldo_ana.cir` carries a one-way peak detector so
  "the rail never falls below its own running maximum" is a number.

### What the AP63203 model does and does not contain

From the datasheet: `VFB` 3.30 V, `fSW` 1100 kHz, `tSS` 4 ms soft-start, `RDS(ON)`
125 mΩ high side / 68 mΩ low side (lumped as one 106 mΩ series resistance at the D = 0.66
operating point), `IPEAK` 2.8 A. The inductor is a **real** inductor with its 46 mΩ DCR, so
the large-signal slew rate `(VIN−VOUT)/L` — which is what actually sets the undershoot of a
1 µs load step — falls out of the deck instead of being asserted. Duty is clamped to
[0, 1], which reproduces the datasheet's 100 %-duty low-dropout mode.

**Assumed, not from the datasheet:** the voltage-loop crossover `FC` (60 kHz, i.e. fSW/18)
and the compensation zero `FZ` (FC/5). Diodes does not publish the internal compensation.
`FC` is swept 30 / 60 / 120 kHz and the sweep is a table in RESULTS.md, so a reader can see
how much of each predicate rests on it. The inner current loop is proportional with a
350 kHz (fSW/π) crossover. The compensation is sized from a separate `COUTDES` parameter
that corners deliberately do **not** touch: the AP63203's compensation is fixed in silicon,
so changing the fitted output capacitors must not silently re-tune the loop with them.

### What the TPS7A2033 model does and does not contain

From the datasheet: `VOUT` 3.30 V, closed-loop DC output impedance 63.5 mΩ (= the 19 mV
load-regulation spec over 1→300 mA, DBV package), `ICL` 520 mA, dropout resistance 483 mΩ
(= `VDO` 145 mV at 300 mA), `tSTR` 750 µs, `VEN(HI)` 0.9 V, the ~150 Ω active discharge, and
the ground current (6.5 µA quiescent, 2 mA at 300 mA).

**Loop bandwidth and output impedance, as the brief required, come from the datasheet's own
transient figure and the reading is stated:** Figure 5-51 (IOUT 1 mA → 300 mA, tRISING 1 µs,
COUT 1 µF) has an AC-coupled output axis of +20 mV to −80 mV. Reading the excursion as
−70 mV for a 299 mA step gives a peak closed-loop output impedance of 0.070/0.299 =
234 mΩ; the peak of |Zout| is the capacitor impedance at crossover, so `FCREF` =
1/(2π·0.234·1e−6) = **680 kHz at COUT = 1 µF**. That is a reading off an axis extent, not a
tabulated number — call it ±30 % — so the harness sweeps 400 / 680 / 1000 kHz (and a
200 kHz outlier) and RESULTS.md carries the sweep. The parasitic pole `FP2` = 1 MHz is
pinned by the datasheet's own stability floor: it is the value that leaves ~56° of phase
margin at exactly the 1 µF minimum COUT the datasheet guarantees.

**Known structural limitation, stated because it bounds what a PASS means:** in this model
the load-step deviation and the phase margin are both independent of COUT (crossover scales
as 1/COUT, so the product that sets the deviation is constant, and the Routh determinant
ratio comes out COUT-independent). The deck therefore **cannot test the datasheet's 1 µF
minimum output capacitance**, and the C26 = 1.1 µF derated PASS is not evidence of
stability at that value. RESULTS.md says this too.

## Negative controls

Each deck carries one registered negative control, chosen to be a realistic defect that the
predicate it targets must be able to see:

| Control | Defect | Must fail |
| --- | --- | --- |
| NC1 | 1 mΩ bridge across D1 (solder bridge, or D1 fitted reversed in its SOD-323 land) | P1c back-feed |
| NC2 | C10/C11 cut to 1 µF effective each | P2a undershoot/overshoot |
| NC3 | U12 EN tied to V5_SYS instead of V3V3_SYS | P3d sequencing |

Two of the controls the task brief named — buck C10/C11 at 2 × 4.7 µF, and LDO C26 at
0.47 µF — turn out **not** to fail. They are run anyway and reported as sensitivity rows,
with the value at which the buck predicate *is* first violated and with the reason the LDO
one cannot be violated by this model. That is why they are not the registered controls: a
negative control has to be able to fail, or it proves nothing about the harness.
